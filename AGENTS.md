# AI-FluxMux — resume here

This folder is the Avalonia desktop app **AI-FluxMux v0.2 beta**. It launches local GGUF models through **llama-server**, can route cloud models, and presents one OpenAI-compatible address to a **Client app** (Cline or Harness).

Open **this folder** as the Cursor workspace. The parent `Workspace` git tree also holds other projects; its `AGENTS.md` is a WinForms layout policy and does not apply here.

Do not restructure `MainViewModel.cs` / `FluxMuxRuntimeService.cs` / `MainWindow.axaml` for GitHub cosmetics while behaviour is still changing. Extract a slice only after that behaviour has settled (Health copy, Compact, idle timeout, fingerprints are the pattern). Decompiler leftovers in `FluxMuxRuntimeService.cs` (`goto IL_*`, `if (1 == 0)`, `num`/`text`/`flag`) have been removed — do not reintroduce them, and do not mix a further split of that file with profile, Validate, or NVFP4 launch work.

## Product facts

- Public Endpoint URL / **Port**: `http://127.0.0.1:5001` (change only if Endpoint settings use another port). That is what Client apps call. Several can be active at once (Cline and Harness together) if they all use this Port.
- **Daemon port**: private listen port for **llama-server** (usually Port+1). AI-FluxMux talks to llama-server there; do not point a Client app at it.
- Client app dropdown is extra setup notes and Harness controls, not exclusive ownership of Port and not routing-dialog naming. Cline and Harness can share Port; dialogs always cover both, and Harness web is detected when it is actually up. The Harness block on Servers (install links, web UI port, settings.yaml) follows that dropdown — shown for Harness, or whenever Harness web is actually up (`ShowHarnessServersPanel`), so a Cline operator is not asked to set a Harness port. The Quick Select launcher and its stop stay ungated (`ShowHarnessSetupPanel`); do not gate those on the dropdown, or a running web chat has no stop. `Help.html` carries that symmetry too: **Cline** and **DeepSeek Harness** are a Heading 2 topic each, linked from their subheadings under *Choosing a Client app for local models*. The Cline topic must keep saying that a new model does **not** need a new task, which is the one place the two clients genuinely differ. The Cline block is the same shape (heading, note, links, status line), but its status is `ClineContextSync.ReadPortStatus` — not found / points elsewhere / points at Port — because Cline is an editor extension with no version AI-FluxMux can read, and pointing at Port is the precondition for Launch syncing it. Do not add a per-model **launcher** for Cline to match Harness: Harness needs a new session to pick up rewritten yaml, while Cline keeps model id `local` and picks up the new model on its next message, AI-FluxMux cannot open a Cline task from outside the editor, and reaching into that webview is what raced it before. Launch runs one Endpoint-settings sync (`EndpointSettingsSync`) for every enabled adapter that already points at Port. Built-ins: `cline-4x`, `harness-yaml`. Optional `EndpointAdapters` array in `fluxmux_config.json` can disable those or add `kind: json-merge` clients (sample: `endpoint-adapters.example.json`). Servers → **Export / Import Endpoint adapters** writes Port + that array only (no secrets, no model profiles) so a bad JSON edit or a reinstall can be recovered. Model Profiles → **Export / Import model profiles** writes a temporary pack that patches live `LocalProfiles` / `CloudProfiles` only when the file is clean (no secrets, no live-config keys); same-name different settings and same-settings duplicate variants are skipped. Do not put a development config in the public zip.
- Client app: OpenAI Compatible, model id `local`, API key can be a single space. Native Cursor Chat cannot reach `127.0.0.1`. That stays out of `Help.html` on purpose: Cursor offers no OpenAI-compatible setting to fill in and says so itself, so the note only distracted a new user working through setup. Do not add it back. Cursor is not a Client app of AI-FluxMux and never appears beside Cline in Help or UI — say **VS Code** alone, and do not "correct" that to "VS Code or Cursor". AI-FluxMux never routes *to* a Client app in the first place: clients call Port, nothing is sent out to them, and Cursor never calls Port because it exposes no OpenAI-compatible setting. Cursor's only role in this project is the IDE the code is edited in.
- Do not point the Client app at `llama-server.exe`. Do not put Harness’s UI port (often 3080) into AI-FluxMux Port. Do not put Discover / Use Discovered Server Port back next to Port — that control copied a listen port into Port and could point the Client app at llama-server or Harness. The scan code can stay unused.
- After UI, gateway, or launch-arg changes: **close and relaunch** AI-FluxMux. Saving `Help.html` rebuilds the Help index without a relaunch. The Help tab loads the newest `Help.html` next to AI-FluxMux.exe, in the folder you started from, or in `%AppData%\AI-FluxMux\` (a Word save in this folder wins over a stale `bin\Debug` copy).
- Default build/test (AI-FluxMux closed): `dotnet build` and `dotnet test`. That is the Debug launcher. Do not AutoStart AI-FluxMux on editor folder-open — it killed the running copy and raced Cline's webview. Parent Workspace task **Start AI-FluxMux (Debug)** (`run_orchestrator.cmd`) is manual: it builds, then starts `bin\Debug\net10.0\FluxMux.Avalonia.exe` detached so closing VS Code or Cursor does not stop AI-FluxMux. That launcher sets the working directory to **this project folder**, not the exe folder (`AVALONIA_START_DIR`), because `HelpHtmlFile` looks next to the exe, in the working directory, and in `%AppData%` — nowhere else. Without it the app reads the `bin\Debug` copy a build left behind and a Word save here is invisible until the next build. Do not "tidy" that back to the exe folder. Do not use `dotnet run` from that task — the editor job kills it. A public install is already its own window.
- Side output is only a file-lock safety valve while AI-FluxMux is **already open**. It must not overwrite `bin\Debug`. `Directory.Build.props` also gives those builds their own `artifacts\obj` tree so they cannot strip compiled XAML from the launcher:

```
dotnet test -p:UseAppHost=false -o artifacts\test-ref
dotnet build -p:UseAppHost=false -o artifacts\test-ref
```

Do not launch from `artifacts\`. If the window flashes and disappears, rebuild Debug with `dotnet build` (no `-o`) and see `Logs\FluxMux_Startup_Error.log`.

A public install (no `.vscode\fluxmux_config.json` walking up from the exe) uses `%AppData%\AI-FluxMux\`. This development tree still uses the workspace `.vscode` file.

Nothing may **require** a write next to the exe, because an installed AI-FluxMux (Program Files, or any MSIX) cannot do it. Each such write falls back to `%AppData%\AI-FluxMux\`: a Help feed update saves there when the install folder refuses (`UpdateCheck`), and `HelpHtmlFile` lists that folder as a Help location so the updated copy is found on age like any other. `StartupCrashLog` tries the exe folder then that folder for both `FluxMux_Startup_Error.log` and `AI-FluxMux-could-not-start.txt` — losing those in a read-only install would hide exactly the failure the operator needs to read. Help pictures resolve beside the loaded `Help.html` and then beside the exe, so a per-user Help still shows the shipped screenshots. Do not add a new write beside the exe without a fallback. First public artifact is a **self-contained win-x64 zip** (`Properties/PublishProfiles/win-x64-selfcontained.pubxml` → `artifacts\publish\AI-FluxMux-0.2-beta`). Code signing is not in this tree. Do not put a development `fluxmux_config.json` or secrets in that zip.

## User-facing names (do not invent synonyms in UI or Health)

| --- | --- |
| AI-FluxMux | This app and its public address |
| Port | Public OpenAI-compatible address for the Client app (usually 5001) |

| llama-server | The process that loads the GGUF |

| model profile / model profile variant | Saved settings for that file |
| Client app | Cline, Harness, or any OpenAI-compatible client |
| Compact | Shorten older turns **forwarded** to llama-server; the Client app still has the full chat |

Health and Diagnostics must name the affected entity (llama-server, the GGUF filename, AI-FluxMux, Client app, model profile). Do not say “the runner” or “the backend” alone. When mentioning the private listen port, say **daemon port** and name **llama-server**.

The calling app was called “Endpoint app” until the v0.2 beta copy pass. In normal API usage the endpoint is the address being called, so Cline and Harness are clients and Port is the endpoint. Operator-facing text (UI labels, Help, Health, routing dialogs) now says **Client app**. Identifiers and stored artefacts keep the original word and must not be renamed: the `EndpointAdapters` config key, `EndpointSettingsSync`, `EndpointAdapterPack`, `EndpointApp`/`SelectedEndpointApp`, `endpoint-adapters.example.json`, and the Servers buttons **Export / Import Endpoint adapters**, which are named after that key. Do not “finish” the rename into those. **Endpoint settings** stays as the Servers group header because it does mean the address AI-FluxMux exposes.

`Help.html` is **UTF-16 with a byte-order mark**, because Word saves it that way and declares `charset=unicode` inside it. A text edit that rewrites the file without that mark leaves the bytes NUL-separated, `File.ReadAllText` decodes them as UTF-8, and every topic and UI note silently disappears. After editing this file with anything other than Word, put the mark back and confirm it decodes (`Shipped_help_html_decodes_the_way_the_app_reads_it`). Do not "fix" it to UTF-8 without also changing that charset declaration, or Word mis-reads it on the next open.

Help copy lives in [`Help.html`](Help.html). Edit it in Microsoft Word: File → Save As → **Web Page, Filtered**, keep the name `Help.html` in this folder (or next to AI-FluxMux.exe). Heading 2 **Interface notes** is omitted from that index; Heading 3 under it is a standing UI note id (`quickselect.hot_routing`). Save the file to refresh those notes without a relaunch. A note keeps the shape it was given — paragraphs and bullets get a line each (`FlattenNoteBlocks`), so write several short points rather than one paragraph. Word wraps its saved source mid-sentence, so `CollectInlines` collapses whitespace as each text node is read and only a `<br>` may break a line; do not restore raw text-node newlines, or Word's file layout shows up as line breaks in the middle of paragraphs on screen. Word also saves a bulleted list as ordinary paragraphs carrying an `mso-list` style plus a bullet character of its own (`mso-list:Ignore`); `IsWordListParagraph` gathers consecutive ones back into a `HelpListBlock` and drops that character, which is what gives a wrapped line its hanging indent in both the Help tab and a UI note. A note marks each item with `HelpHtmlParser.NoteBullet`, and `OptionInfoNote` lays that out as marker plus text — do not render a note into one `TextBlock` again. A note may name a live value instead of stating it: `{Address}`, `{Port}`, `{ProfileContext}`, and `{HarnessChatUrl}` are filled by `HelpUiNotes.Fill` from values `MainViewModel.PublishHelpNoteValues` sets, and an unknown name is left showing as typed so a Word typo is visible rather than blank. Add a token rather than pushing a whole note back into code. The `settings.yaml` retry detail lives in **Appendix E — Harness settings.yaml**, not in the note beside those buttons. Turn off Word smart quotes and auto-dashes. Put the yaml sample in Preformatted text or a one-cell Consolas table.

The Help tab renders the three heading levels at three sizes: Heading 1 is a section banner that also groups the index (topics list under the banner above them), Heading 2 is the topic, Heading 3 is a subheading. Prose is capped near 90 characters a line while tables, code samples, and pictures may use a wider column. ## Behaviour that is easy to break

- **Compact** only shortens forwarded history when the loaded Context is actually filling (or the prompt already exceeds it). Do not compact every turn. Compact cannot shrink a single over-full Cline turn.
- Prompt-token estimates must not treat embedded image bytes (data-URI base64) as text. Count a small per-picture allowance. A screenshot on an Images-off load is a capability miss, not a Context overflow 400.
- **Route requests** is always prompted. Cloud and local hops stay in this Client-app chat when both are already running (including Harness). A local-to-local switch that FluxMux offers reloads llama-server and is not safe in that chat — new Cline task or Harness chat. Overlay-only (temperature / max tokens) can apply without a reload, but FluxMux does not prompt a route switch for that. Offer the ready cloud only when the loaded local is already **GPU + CPU** or **CPU only** and the forwarded turn is large enough to make RAM spill worse. A GPU-only local that still fits stays local. Whenever the loaded local cannot take this turn (Context filling, RAM spill, or a capability miss) and a cloud hop is offered, hold this Client-app request for Switch to that cloud; 400 only if they keep local or the wait times out (llama-server was not asked). Closing that dialog must not steal focus from the Client app. A Load suggested local reload must not 400 that turn before the cloud hop can finish. Do not append character or token stats to those operator dialogs. Do not invent a Client app remaining-percent. After Switch to cloud, later turns the loaded local could have taken are offered back on the next capable turn. After a 400 or llama-server reload: that turn is over. Harness needs a new chat. Cline keeps model id `local` — the next message in this task can use the new model once it is ready; start a new Cline task if the same error would repeat, after a hang abort / Keep-end, or if Cline is looping a command. Live-Switch Testing probes Port after each profile is ready; it does not prove an in-flight Cline turn survives a reload.
- Harness **0.1.2+** gates the web UI with a `?token=` URL printed by `dsh web`. Opening `http://127.0.0.1:3080` without that token returns 401 (`/api/llm.providers` fails). AI-FluxMux starts `dsh` with `--no-open`, waits until that URL is in `fluxmux-harness-launch.log`, and opens it. If the UI is already up with 401 and no token is on file, **Harness web chat** restarts Harness web so the user does not have to paste a URL. Never `npm install`.
- Harness `settings.yaml` must not hide a turn FluxMux could offer a different local for. If a validated profile has Images on, Reasoning on, or a larger Context / max tokens, advertise that in yaml even when the loaded profile does not. FluxMux then offers **Load suggested** on Diagnostics / routing pop-up. Harness's own model picker is a different message. New Harness session after yaml write.
- `/v1/models` (and `/models`) is the one channel that reaches a Client app with no adapter, so it carries the **loaded** model's Context (`context_length`, `max_model_len`, `meta.n_ctx`), reply budget (`max_tokens`, `max_output_tokens`, `meta.n_predict`), and Images (`supports_images`, `supports_vision`, `meta.vision`) — several spellings because none of this is in the OpenAI spec. Reply budget is read back off the launch args (`ReadIntArg(args, "-n")`) so it is what llama-server was told, not what a profile hoped for. A capability AI-FluxMux does not know is **left out**, never asserted false: a client that is told Images are off will not offer to attach one, and that turn never reaches the routing offer. This does not replace `EndpointSettingsSync` — Cline takes Context from its own settings and defaults to 128000, Harness learns the provider exists only from `settings.yaml`, and neither Auto compact nor a base URL has a field in a models list.
- **Max tokens** is llama-server `-n` (reply budget), not VRAM. VRAM is mostly `-c` (Context) plus weights and an optional mmproj.
- **Validate** is a tiny “reply ready” probe. It does not prove a long Cline write.
- Settings-only AutoTune edits the form; **Save** keeps it, **Revert** discards it. Experimental speed AutoTune reloads llama-server. After Save, AutoTune must not lower a hand-tuned max tokens / Context / temperature / reasoning / chat template / parser / unban; it may still change GPU, batch, threads. **Images is not a wizard setting** — AutoTune works around Enable / Max image edge / projector. Images on reserves VRAM from the projector plus Max image edge (scales with edge² and leftover GPU GiB) and **may lower** a text-only Context that now exceeds the Images-on advice ceiling. When VRAM math saturates 262144, text-only Context scales leftover GiB to the known-working **213056** at ~12 GiB leftover (not 81% of 262144). Do not write 262144 as advice. Do not default an unknown GGUF to 262144.
- Overlay temperature/max tokens can apply without a llama-server reload; launch-critical fingerprint changes require Launch. Only one llama-server is loaded. A second local Quick Select slot must not show as loaded or **Hot — standing by** (that label is for a ready cloud while a local is answering). Harness `name` follows the llama-server profile that is actually running, not another variant of the same GGUF.
- Images on loads `mmproj` for the whole session (~0.9 GiB projector here) even if no picture is sent. An `mmproj*.gguf` is a vision projector, not a local model. Do not Validate or Launch it as `-m`. Pair it under Images on the matching GGUF profile.
- llama-server log lines in Diagnostics are labeled `Last llama-server output`. Verbosity is high at startup; that is not an OOM by itself. Do not write raw llama-server tails (tabs, “UI is disabled”) into the Model Profiles status row — keep those in Diagnostics.
- Launch countdown follows a **cold** llama-server load, not a **warm** cached hit, so a warm load can finish sooner.
- **Make New Variant** needs a name in the box beside the button. An empty click shows **Name your variant first**. Creating a local model profile must stay on that new row; do not leave the previous expander selected.
- FluxMux launches `llama-server.exe` only. Leftover zip CLIs (`llama-qwen2vl-cli.exe`, `llama-llava-cli.exe`, and similar) can trip Windows Defender `Wacatac.C!ml`. That is a known false positive. Exclude `C:\AI_Workbench\llama-server`, not all of `C:\AI_Workbench`. Do not turn Defender off.
